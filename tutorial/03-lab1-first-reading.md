# 實作 1:接上 IMU,讀出第一筆資料

目標:把 CMP10A 接上電腦,用校正工具的「即時資料檢視」看到原始數值,
並確認靜置時的讀數符合單元 1 的物理預期。**本實作不寫入任何設定**。

## 步驟 1:確認裝置與環境
IMU 已在[單元 0](00-usb-device-naming.md) 命名為 `/dev/usb_imu`。確認名稱存在,並執行環境檢查:

```bash
ls -l /dev/usb_imu          # 應顯示 /dev/usb_imu -> ttyUSB0(編號依電腦而異)
python3 imu.py              # 選 7 環境檢查
```

macOS 改為確認 `ls /dev/cu.usbserial*`。環境檢查全部通過再往下。

## 步驟 2:進入即時資料檢視
```bash
python3 imu.py
# 選 4 IMU 校正工具(自動使用 /dev/usb_imu)→ 選 1 即時資料檢視
```

畫面每秒更新數次,格式大致如下(數值是本 repo 作者的實測,你的會不同):

```
accel=(  0.07,  0.01,  9.82) m/s^2  gyro=( 0.000, 0.000, 0.000) rad/s  angle=(  0.09, -0.41,177.02) deg  mag=(118,-2475,-2495) LSB  T=29.8C
```

工具已把模組送出的資料換算成物理單位。
`Ctrl+C` 回到選單。

## 步驟 3:靜置觀察
把模組**平放在桌上,Z 軸(元件面)朝上,不要碰**。逐項對照:

| 觀察 | 物理預期 | 若不符合 |
|---|---|---|
| accel z | ≈ +9.8 m/s²;x、y 接近 0 | 差超過 0.5 → 桌面不平或加速度計需校正(實作 2) |
| accel 抖動 | 每次更新變動約 ±0.02 m/s² | 這是雜訊 (noise),不是 bias;bias 是平均值偏離 0 或 9.8 的部分 |
| gyro | 三軸 ≈ 0 rad/s | 有固定非零值 → 陀螺儀 bias |
| angle roll / pitch | 接近 0° | accel 的 x、y 偏離 0 越多,roll、pitch 偏離 0° 也越多 |
| angle yaw | 任意值,但應**穩定** | 若緩慢變化 → 磁力計受干擾或未校正 |
| mag 三軸 | 固定值,抖動約 ±20–30 LSB | 若跳動大 → 附近有物體在移動,例如手機 |
| T | 室溫上下,緩慢上升 | 模組通電後會自熱,這也是為什麼軟體校正要先暖機 |

另一個檢查方法:accel 三軸的合成大小(三軸平方和開根號)應為 9.8 左右,而且不隨模組方向改變。
磁力計同理,三軸的合成大小在轉動時應維持不變(單元 3 會用到)。

## 步驟 4:動一動
每個動作列有預期的變化,操作後對照畫面:

1. **把模組立起來,X 軸朝上**。觀察 accel 三軸與 roll、pitch。預期:9.8 m/s² 移到 X 軸,pitch 約為 ±90°。
2. **沿桌面平移模組**(不旋轉)。觀察 accel、angle、gyro。
   預期:accel 短暫變化,gyro 與角度幾乎不動;融合濾波器對陀螺儀的權重高於加速度計的瞬時值。
3. **原地繞 Z 軸慢慢轉 90°**。觀察 yaw 變化量、accel、mag 三軸與合成大小。
   預期:yaw 變化約 90°,accel 不變,mag 的 x、y 改變而長度不變。
4. **快速轉一下再停住**。觀察 gyro 的峰值,以及停止後 yaw 是否持續變化。

動作 3 的 yaw 變化量若明顯偏離 90°(例如 75° 或 105°),是磁力計未校正的症狀,實作 2 處理。

## 常見問題

- **選單打不開序列埠**:同一時間只能有一個程式開序列埠。
  Windows 上若開著 WitMotion 上位機(repo 內 `IMU standard PC software` 資料夾),先關掉。
- **數值全是 0 或畫面不動**:鮑率不對(曾被改過)或線沒接好;環境檢查會列出序列埠但看不出鮑率。
- **WSL 裝置忽然消失**:在 `wsl_usb_auto` 選「查看所有規則」確認監聽仍在執行,必要時選「啟動監聽」。

## 本實作的結果

完成後應已確認:靜置時 accel 的 z 軸約為 9.8 m/s²、gyro 接近 0、mag 穩定;並得到校正前「水平轉 90°」的 yaw 變化量。
後者在實作 2 校正後會再量一次,用來比較校正前後的差異。

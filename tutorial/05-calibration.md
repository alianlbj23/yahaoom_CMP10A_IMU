# 單元 4 + 實作 2:校正

## 為什麼要校正

感測器的輸出由三部分組成:真值、bias、noise。

- **noise(雜訊)**:每次取樣都不同的隨機部分。平均可以壓低,校正消不掉。
- **bias(偏移)**:固定或緩慢變化的部分。**校正要處理的就是它**。

校正 (calibration) 的定義:用**已知的輸入**(重力恰好 1 g、靜止時角速度恰好 0、地磁場大小固定)
去量出 bias,然後從之後的量測值中扣掉。

沒有已知輸入就沒有校正。這也是為什麼每一項校正都有「要在哪裡做」的要求:
那個「哪裡」就是在提供已知輸入。

## 四種誤差,四種校正

| 誤差 | 已知輸入 | 校正方式 | 本 repo 的選項 |
|---|---|---|---|
| 加速度計 bias | 水平靜置時 x、y 為 0,z 為 +9.8 m/s² | 量平均值,扣掉與理想值的差 | 2(硬體)、9(軟體) |
| 陀螺儀 bias | 靜止時角速度為 0 | 量平均值,全部當作 bias | 9(軟體);硬體選項 2 同時也會處理 |
| 磁力計 hard-iron | 轉動時三軸合成大小不變 | 各軸 (max + min) / 2 為偏移 | 3、4(硬體)、10(軟體) |
| 磁力計 soft-iron | 同上 | 橢球擬合成球 | 3(硬體球面擬合) |

另外三項不是校正誤差,而是**定義零點**:

| 選項 | 做什麼 | 已知輸入 |
|---|---|---|
| 5 航向歸零 | 現在的方向 = yaw 0° | 你決定的「正前方」 |
| 6 角度參考 | 現在的姿態 = roll 0°、pitch 0° | 機器人放在水平地面 |
| 7 高度歸零 | 現在的氣壓高度 = 0 m | 你決定的參考高度 |

## 硬體校正 vs 軟體校正

| | 硬體校正(選項 2–7、11) | 軟體校正(選項 9、10) |
|---|---|---|
| 結果存在哪 | 模組的 flash | 主機 `config/imu_calibration.yaml` |
| 誰套用 | 模組內部,輸出已修正 | ROS driver 啟動時讀 YAML,發佈前扣掉 |
| 換電腦 | 跟著模組走 | 要帶著 YAML |
| 演算法 | WitMotion 的,未公開 | 取平均值、取最大最小值的中點 |
| 復原 | 11 恢復原廠 | 刪 YAML |
| 用途 | 主要校正 | 補硬體校正剩下的殘差;教學上看得到數字 |

本課兩種都做:先硬體,再軟體。

軟體校正的做法:靜置時取多筆資料的平均值作為加速度計與陀螺儀的偏移;
磁力計則取各軸最大值與最小值的中點 `(max + min) / 2` 作為 hard-iron 偏移。

`(max + min) / 2` 等於圓心的理由:轉一整圈,X 軸的讀數會從圓的最左邊掃到最右邊,
兩端的中點就是圓心的 X 座標。所以**沒轉滿、兩端沒碰到,圓心就算錯**。這就是工具要顯示三軸覆蓋進度的原因。

## 誤差的量級

| 誤差來源 | 大小 | 造成的結果 |
|---|---|---|
| 加速度計 bias | 0.1 m/s² | 傾角誤差約 0.6° |
| 陀螺儀 bias | 0.1 °/s | 累加 1 分鐘後角度差 6° |
| 磁力計 hard-iron 偏移 | 場強的 10% | yaw 誤差最大約 6°,且隨方向改變:有的 90° 量成 80°,有的量成 100° |

## 實作 2 步驟

> 進入方式:`python3 imu.py` → `4 IMU 校正工具`。硬體校正**會永久寫入模組 flash**,
> 工具在每次寫入前都會印注意事項並問 `(y/N)`,看完再按 y。
> 中途失敗可重做;做壞了用 11 恢復原廠。

### 步驟 0:記錄校正前的狀態
選 `8 讀取 IMU 內部偏移暫存器`,留意 AXOFFSET…HZOFFSET 九個值。
全是 0 表示從未做過硬體校正。這些值在步驟 2、3 之後要再讀一次比較。

### 步驟 1:加速度計水平校正
- 在哪裡:**真正水平的桌面**,用水平儀確認。高度不重要,水平最重要。
- 怎麼做:模組 Z 軸朝上平放,選 `2`,確認後**不要碰**,等進度條跑完(5 秒)自動儲存。
- 原理對應:提供已知輸入「x、y 為 0,z 為 +9.8 m/s²」。

做完回到 `1 即時資料檢視`,accel x、y 應比實作 1 更接近 0,roll、pitch 更接近 0°。

### 步驟 2:磁力計校正
- 在哪裡:**最終安裝位置、實際使用環境**。本課模組尚未裝上機器人,就在桌上做,但要:
  離筆電、鐵桌腳、手機 20 cm 以上;整組的人把手機放遠。
- 怎麼做:選 `3 磁力計校正 球面擬合`,確認後**繞 X、Y、Z 三軸各緩慢轉數圈**。
  畫面有三軸進度條與 `缺 Y Z` 之類的提示,補法:X 不夠就繞 Y 或 Z 轉,依此類推。
  三軸都 100% 出現 `[完成]` 後按 Enter → 儲存。
- 原理對應:提供已知輸入「合成大小不變」,工具要蒐集球面上各方向的點才能擬合。

注意:進入磁力計校正模式後,CMP10A 的加速度、陀螺儀、角度輸出會**凍結**(實機觀察,
錄製檔 `cmp10a_magcal_mode_rotating_9600.bin`),只有磁力計在更新。所以進度條只能從磁力計算,
這就是為什麼「轉慢一點、每個方向都要到」比「轉很多圈」重要。

機器人太大、無法三軸翻轉時,改用選項 4「雙平面」:水平繞 Z 轉一圈,立起來再繞另一軸轉一圈。
此法蒐集到的方向較少,soft-iron 的三維形狀估計不完整,只能處理 hard-iron 與兩個平面內的變形。

### 步驟 3:讀暫存器,看發生了什麼
再選 `8`。AXOFFSET、AYOFFSET 和 HXOFFSET…HZOFFSET 應該變了。
這些數字就是模組在 flash 裡記住的 bias。**數字改變只代表已寫入,不代表校正正確**。驗證在實作 3。

### 步驟 4:定義零點
- 選 `5 Z 軸航向歸零`:把模組的 X 箭頭對準你選定的「正前方」(例如桌子的長邊),確認,1 秒完成。
- 選 `6 設定角度參考`:模組在水平桌面上,確認,1 秒完成。此時 roll、pitch 會變成接近 0。
  本課的模組沒有裝歪,這一步效果看不出來;裝到機器人上後才是它的用處。

這兩項不是校正,是告訴模組「我要以這裡為 0」。每次重新安裝都要重做。

### 步驟 5:軟體靜態偏移
- 在哪裡:水平靜置,且**模組已通電暖機約 5 分鐘**(以即時資料檢視中的溫度 T 是否已穩定判斷)。
- 怎麼做:選 `9`,工具取 50 筆(約 5 秒)算平均,寫入 `config/imu_calibration.yaml`。
- 完成後 `cat config/imu_calibration.yaml`,查看 `gyro_bias`、`accel_bias` 的數值。

數字感:`gyro_bias` 多半在 10⁻³ rad/s 量級。換算成 °/s(乘 57.3)再乘 60,就是這顆陀螺儀若不校正、一分鐘會漂幾度。
`accel_bias` 如果超過 1 m/s²,工具會警告:幾乎可以肯定模組沒放平。

### 步驟 6:軟體 hard-iron(選做)
選 `10`,同步驟 2 的轉法,三軸覆蓋達 95% 自動結束(最長 90 秒)。
看 YAML 的 `mag_offset`:這就是 (max + min) / 2 算出的圓心。
把它和步驟 3 讀到的 HXOFFSET…HZOFFSET 比較:
硬體校正已經把大部分 hard-iron 吃掉了,軟體這層算出的偏移應該小很多。如果不小,其中一次沒轉滿。

## 校正順序的邏輯

repo README 建議的順序是:恢復原廠(需要時)→ 加速度計 → 裝上機器人 → 磁力計 → 角度參考 → 航向歸零 → 高度歸零 → 軟體校正 → 驗證。

加速度計排在裝機前、磁力計排在裝機後,原因如下。
加速度計的已知輸入是「水平」,模組單獨放桌上最容易保證;磁力計的已知輸入是「地磁場 + 固定干擾」,
而固定干擾只有裝上去才存在。順序就是跟著「已知輸入在哪裡最容易取得」走。

## 本單元重點

- 校正 = 用已知輸入量 bias 並扣掉;noise 靠平均,校正不管
- 加速度計要水平、陀螺儀要靜止、磁力計要轉滿三軸且合成大小不變
- 硬體校正存 flash 跟著模組;軟體校正存 YAML 跟著電腦
- hard-iron 偏移 = (max + min) / 2,沒轉滿就算錯
- 零點定義(航向、角度參考、高度)不是校正,每次安裝都重做
- 讀到暫存器變了 ≠ 校得好;驗證是下一個實作

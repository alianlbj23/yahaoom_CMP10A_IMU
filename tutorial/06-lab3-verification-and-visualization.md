# 實作 3:驗證與可視化

目標:用**已知的參考**判斷實作 2 的校正是否成功。分兩層:以校正工具量角度(步驟 1),以 Foxglove 檢查磁力計的圖形(步驟 2)。

## 為什麼要驗證

校正工具顯示「完成」只代表指令已送達模組,不代表校正正確。下列三種情況都不能當作校正成功的證據:

| 情況 | 不能當作證據的原因 |
|---|---|
| 工具顯示完成 | 只表示指令送出且模組有回應 |
| 選項 8 讀到的偏移值改變 | 只表示有寫入模組,寫入的值可能是錯的 |
| 輸出的數字穩定 | 沒校好的模組同樣輸出穩定、看似合理的數字 |

判斷的方法和校正相同:**與已知的參考比較**。水平面是已知的 0°,方盒子的邊是已知的 90°,轉一圈回原位是已知的 0°。

## 步驟 1:以角度驗證
`python3 imu.py` → `4` → `12 姿態檢視 / 校正驗證`。畫面:

```
roll(X)   +0.01°  pitch(Y)   -0.02°  yaw(Z) +111.71°  高度  -31.12 m
```

- `Enter`:把目前姿態記成參考點,之後顯示相對變化 Δ
- `r`:清除參考點;`q`:離開

依序做下表的五項檢查。合格值是本 repo 作者以同型模組實測的經驗值,不是原廠規格。

| 檢查 | 怎麼做 | 合格 | 檢查的是 |
|---|---|---|---|
| 水平 | 放在水平面(水平儀確認) | roll、pitch 都在 ±0.5° | 選項 2 加速度計、6 角度參考 |
| 傾斜 90° | 按 Enter,靠著方盒子立起來 | Δpitch 或 Δroll ≈ ±90°,誤差 ±1° | 選項 2 加速度計 |
| yaw 每轉 90° | 靠著方盒子的邊,每轉 90° 前按 Enter | Δyaw 每次約 ±90°,誤差 ±3° | 選項 3 / 4 / 10 磁力計 |
| 轉一圈回原位 | 對齊桌上參考線按 Enter,轉 360° 對回去 | Δyaw 回到 0,誤差 ±3° | 磁力計 |
| 靜置漂移 | 靜置按 Enter,等 3–5 分鐘 | Δyaw 幾乎不變 | 選項 9 陀螺儀偏移 |

五項全部合格,才算桌上驗證通過。

最能分辨磁力計好壞的是「yaw 每轉 90°」。磁力計沒校好的典型症狀是四次分別量到 80°、100°、85°、95°:
總和仍是 360°,所以只做「轉一圈回原位」看不出問題,兩項都要做。

把實作 1 的「水平轉 90°」yaw 變化量與現在的結果比較,即可看出校正的效果。

不合格時回實作 2 重做對應的項目。重做前先確認條件是否成立,條件不變,重做的結果也不會變:

- 桌面是否確實水平(以水平儀確認)
- 磁力計校正時三個軸是否都轉滿
- 手機、筆電、鐵製品是否離模組 20 cm 以上
- 模組是否已通電數分鐘

## 步驟 2:以磁力計的圖形驗證
離開校正工具(校正工具和 driver 不能同時開序列埠),然後:

```bash
python3 imu.py
# 選 2 啟動 IMU + Foxglove bridges → 是否開放區網:n
```

容器啟動後印出連線資訊。開 [app.foxglove.dev](https://app.foxglove.dev)(或桌面版)→ Open connection →
Foxglove WebSocket → `ws://localhost:8765`。

做三件事:

1. **3D 面板**:Display frame 設 `world`。轉動模組,看 `imu_link` 跟著轉。
   畫面上的姿態應與手上模組的姿態一致。
2. **Plot 面板**:加 `/imu/data.linear_acceleration.z`。靜置時約 9.8。
   再加 `/imu/data.angular_velocity.z`,轉一下看到尖峰。
3. **磁力計 X–Y 圖**:Plot 面板 General → X-axis value type 改 `Path (accumulated)`,
   X 填 `/imu/mag.magnetic_field.x`,Series 只留 `/imu/mag.magnetic_field.y`。
   模組水平、原地慢慢轉一圈。

第 3 項是磁力計校正的圖形驗證,依畫出的形狀判斷:

| 形狀 | 意義 |
|---|---|
| 接近正圓,圓心接近原點 | hard-iron 已補償,校正良好 |
| 圓,但圓心偏離原點 | hard-iron 未補償,或有跟著模組動的鐵件 |
| 橢圓 | soft-iron |
| 某個角度凹進去 | 轉到那個方向時旁邊有鐵件 |

另一項數字檢查:在 Plot 面板同時顯示 `/imu/mag.magnetic_field.x`、`.y`、`.z` 三條線,轉動模組。
三條線各自起伏是正常的;三軸的合成大小(三軸平方和開根號)應幾乎不變,變動超過約 10% 表示受到干擾或校正不良。

軟體校正(選項 9、10)的 YAML 是 driver 啟動時載入,所以現在看到的 `/imu/mag` 已經扣掉 `mag_offset`;
硬體校正的結果則在模組內就扣掉了。想看「完全未校正」的圓,得恢復原廠並刪掉 YAML。

## 步驟 3:檢查 ROS 2 的輸出(有時間才做)

另開一個終端機,`python3 imu.py` → `5 進入容器 shell`:

```bash
ros2 topic list
ros2 topic hz /imu/data              # 約 10 Hz
ros2 topic echo /imu/data --once     # 看 orientation 四元數、covariance
ros2 topic echo /imu/mag --once
```

檢查兩件事:`orientation` 四個數的平方和應為 1;`linear_acceleration.z` 靜置時應為 +9.8(REP-145)。

## 驗證通過的條件

| 層次 | 內容 | 通過條件 |
|---|---|---|
| 角度(步驟 1) | 水平、傾斜 90°、每轉 90°、轉一圈回原位、靜置漂移 | 五項皆在合格範圍內 |
| 圖形(步驟 2) | 磁力計 X–Y 圖、三軸合成大小 | 圖形接近正圓且圓心在原點附近;合成大小變動在約 10% 以內 |

兩層都通過,表示模組在桌上、目前的環境下校正成功。
模組裝上自走車後,周圍的鐵件與馬達不同,須在最終安裝位置重做磁力計校正並重新驗證。
